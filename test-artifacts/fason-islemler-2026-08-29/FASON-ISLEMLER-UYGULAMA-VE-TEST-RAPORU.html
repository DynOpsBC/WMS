2. Yapılan geliştirme

Fason üretim emri / barkod→ Fason operasyon + firma→ Malzeme ve miktar seçimi→ Doğrudan transfer postu→ Transfer irsaliyesi + stok izi
  • Standart Released Production Order → Prod. Order Routing Line → Work Center zinciri kullanıldı; paralel bir fason emri yaratılmadı.
  • Yalnız Subcontractor No. atanmış iş merkezleri listeleniyor.
  • Hedef fason depo, iş merkezinin standart Location Code alanından geliyor. Boşsa, kaynakla aynıysa veya bin zorunlu lokasyonda To-Production Bin Code eksikse post duruyor.
  • Onayda standart Direct Transfer oluşturulup post ediliyor; kaynak stok düşüyor, hedef fason lokasyonu aynı işlemde artıyor ve kayıtlı transfer sevki oluşuyor.
  • Her malzeme hareketi üretim emri, operasyon, bileşen, firma, transfer emri, irsaliye, kullanıcı, tarih, LP, lot ve seri bilgileriyle audit tablosuna yazılıyor.
  • GUID işlem anahtarı ve transfer irsaliyesi uzlaştırması aynı terminal isteğinin timeout/tekrar durumunda iki kez stok düşmesini engelliyor.

5. Canlıya alma kapıları

  1. Windows/CI AL toolchain ile al/app.json 1.14.0.90 derlenmeli ve BADE sandbox’a publish edilmeli.
  2. Fason iş merkezlerinde Subcontractor No., Location Code ve bin zorunluysa To-Production Bin Code doğrulanmalı; Inventory Setup / Direct Transfer Posting seçeneği “Receipt and Shipment” olmalı.
  3. Sandbox’ta bir test fason üretim emriyle şu dört gerçek post yapılmalı: tam LP’siz, kısmi LP’siz, tek LP lotlu, çok LP lotlu.
  4. Her postta Transfer Shipment, kaynak/ hedef Item Ledger miktarları ve audit satırı aynı belge numarası üzerinden karşılaştırılmalı.
  5. Bu kapılar geçmeden production publish yapılmamalı; geçtikten sonra aynı AL paketi ve BADE 1.14.70 release APK kullanılmalı.
